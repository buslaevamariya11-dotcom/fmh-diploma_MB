# План проверки и автоматизации «В Хосписе»

Дата подготовки: 23.10.2026. Основание: задание дипломного проекта и исходный архив `fmh_android_updated.zip`.

## 1. Цель и состояние работы

Проверить реализованные пользовательские функции мобильного приложения и подготовить план автоматизации повторяемых UI-сценариев. Результаты ручной проверки 23.10.2026 указаны в Check.xlsx и Cases.xlsx. Из 60 проверок: 50 пройдены, 2 не пройдены, 3 требуют уточнения ожидаемого поведения, 4 заблокированы предусловиями, 1 выполнена частично и оставлена со статусом «Не выполнено». Подтверждения находятся в папке evidence. Анализ исходников не считается выполнением ручного теста.

Это первая часть диплома: планирование, тест-дизайн и ручная проверка приложения. Руководителю передаются исходный проект, Plan.md, Check.xlsx и Cases.xlsx. Реализация UI-тестов, подключение Allure и сравнение времени начинаются только после принятия этой части преподавателем.

## 2. Объект и границы

Пакет `ru.edu.qamid`, версия `1.0.0`, versionCode 14; Kotlin, Android Views, Navigation, Room, Retrofit, Hilt. В исходном проекте minSdk 23, compileSdk/targetSdk 36.

Включены: авторизация и выход, сохранение сессии, главная с тремя новостями, список и карточки новостей, сортировка, фильтры категории/периода/активности, панель управления, создание/редактирование/удаление своих тестовых новостей, активность публикации, тематические цитаты раздела «Наша миссия», сообщения об ошибках, восстановление после изменения состояния приложения.

Исключены: нагрузочное тестирование сервера, изменение серверного кода, медицинские процессы и обработка данных пациентов, функции заявок/документов/дежурств, отсутствующие в действующей навигации. Отдельные строки ресурсов не доказывают наличие пользовательского функционала. Проверки безопасности ограничены маскированием пароля, выходом и доступом к панели; полноценный аудит безопасности не заявляется.

## 3. Источники и ожидаемое поведение

- Задание: API 36, UI-тесты, Allure, шаги с проверками, скриншоты при падении, сохранение APK после тестов.
- `app/src/main/res/navigation/nav_main.xml`: состав экранов и переходов.
- `app/src/main/java/ru/edu/qamid/ui/`: пользовательские действия и валидация.
- `adapter/`, `viewmodel/`, `dao/NewsDao.kt`: отображение, сортировка и фильтрация.
- `app/src/main/res/values-ru/strings.xml`: русские подписи и ошибки.

Ожидания, выведенные из кода, отмечены в Cases. Код служит основой для предварительных кейсов, но не заменяет согласованную спецификацию. Обратный период, оба выключенных статуса и секунды последней минуты требуют согласования ожидаемого поведения.

## 4. Окружение и данные

Основное окружение: эмулятор Android API 36, русский язык, портрет, стандартный шрифт, зафиксированный часовой пояс устройства. Записать модель, точный API, разрешение, локаль, часовой пояс, версию приложения и время начала. Дополнительно: альбомная ориентация, увеличенный шрифт; другие API - только как расширение, не замена API 36.

JDK 17 или 21, Gradle Wrapper 8.13, AGP 8.12.2, Android SDK Platform 36 и Build Tools 35.0.0. Сеть нужна для зависимостей и backend `https://students.netoservices.ru/qamid-diplom-backend/`.

Использовать выданную учебную учётную запись. Пароль передавать через окружение запуска; не записывать в Git, таблицы, логи и снимки. Наличие административного доступа проверять фактически: без него сценарии панели фиксировать как заблокированные предусловием. Проверку ограничения роли выполнять только с отдельной предоставленной неадминистративной учётной записью.

Все изменяемые данные принадлежат тесту: префикс `DIPLOMA-`, уникальный суффикс. Перед изменением зафиксировать ID/заголовок своей записи, после сценария удалить только её. Чужие новости не изменять. Сортировка требует хотя бы двух разных дат; проверки списков - непустых данных. Пустые состояния получать фильтрацией либо на выделенном наборе, не удалением общей базы.

## 5. Виды тестирования

Функциональное позитивное и негативное; smoke; регрессионное; проверка обязательных полей и классов эквивалентности (пусто/пробелы/валидное значение); границы дат; навигация; интеграция UI-backend; совместимость с API 36; состояния сети и жизненного цикла; базовая доступность и читаемость.

Порядок: сборка и установка  smoke вход/главная/новости/миссия   чтение и фильтры   собственные CRUD-данные   ошибки и восстановление   совместимость и визуальные проверки.

## 6. Ручное выполнение

1. Установить APK, записать окружение и исходное состояние. Выполнить предусловия каждого кейса.
2. Проверять результат каждого шага; при расхождении зафиксировать фактическое поведение, время с часовым поясом, ID своей новости, скриншот и необходимые обезличенные логи.
3. В Check/Cases ставить «Пройдено», «Не пройдено», «Заблокировано» либо «Не выполнено». «Заблокировано» - только если проверка действительно начата и обнаружено невыполненное предусловие.
4. Для дефекта указать сборку, окружение, предусловия, шаги, ожидаемый/фактический результат, воспроизводимость и доказательства. Подозрение по коду не считать воспроизведённым дефектом.
5. Замерять длительность каждого кейса отдельно, включая проверки и стандартное восстановление данных; анализ дефектов учитывать отдельно.

## 7. План автоматизации после принятия первой части

Предварительно планируется автоматизировать TC-001-TC-043 средствами Kotlin, Espresso, JUnit4 и UI Automator. TC-033-TC-038 можно объединить в один сквозной сценарий с собственными уникальными данными и обязательной очисткой. Окончательный состав согласуется после ручного прогона и замечаний преподавателя.

Планируется выделить группы авторизации, новостей, фильтров, формы создания, цитат и жизненного цикла новости. Действия завершаются проверкой наблюдаемого результата. Ожидания ограничиваются таймаутом, элементы адресуются по устойчивым идентификаторам. Для ручных TC-044-TC-060 причины отсутствия планируемой автоматизации указаны в Cases; часть проверок требует согласования требований или дополнительного окружения.

Во второй части будут настроены Allure, названия и описания тестов, шаги и снимки при падении. После реального прогона будут подготовлены README.md с запуском, allure-results.zip и Result.md с измеренным сравнением времени одинакового набора руками и автоматически. Флаг сохранения APK после тестов будет добавлен на этапе настройки автоматизации.

## 9. Фактический прогон первого этапа

Устройство: эмулятор Pixel 5, Android 16 API 36, x86_64, 1080x2340. Приложение 1.0.0 (14), пакет ru.edu.qamid. Использован готовый debug APK из исходного архива. Язык приложения ru-RU, часовой пояс устройства GMT. Дата протоколирования 23.10.2026, Europe/Samara (UTC+4). Исходный проект не изменялся; самостоятельная пересборка в этом прогоне не подтверждалась.

Сценарии выполнялись через интерфейс приложения с последовательным наблюдением экранов. Для управления эмулятором использован существующий сервер ADB. Для сравнения наборов новостей прочитаны только ID, заголовки, категории, даты и статусы из локального кэша. База, токены и реквизиты в материалы сдачи не включены.

Исходно в панели восемь активных записей. На первом открытии публичного списка наблюдалось шесть карточек, при более позднем открытии пять. Это наблюдение не классифицировано как дефект: состав учебного стенда и правила отображения проверяются на момент конкретного сценария. Собственные новости DIPLOMA-20261023-1905, DIPLOMA-REQUIRED и DIPLOMA-SCHEDULED после проверок удалены. В итоговом кэше снова восемь исходных записей, собственные тестовые заголовки отсутствуют. Сеть включена, шрифт восстановлен 1.0, блокировка поворота снята.

В нескольких проверках использованы эквивалентные значения латиницей вместо русских образцов, текущее время вместо 12:00 либо завтрашняя допустимая дата. Отличия явно указаны в фактических результатах. Достоверный отдельный замер каждого кейса не проводился, поэтому столбцы времени оставлены пустыми. Сравнение времени относится ко второму этапу и потребует отдельного замера одинакового набора проверок.

### Непройденные проверки

BUG-001, TC-005, приоритет P1. При неверных реквизитах HTTP 401 сопровождается общим сообщением «Что-то пошло не так. Попробуйте позднее» вместо «Неверный логин или пароль». Вход отклонён. Воспроизведение: открыть авторизацию, ввести несуществующий логин и неверный пароль, нажать Войти. Подтверждение: evidence/TC005-invalid-error.png и evidence/auth-http-status.txt.

BUG-002, TC-007, приоритет P1. После выхода из аккаунта и последующего поворота приложение завершилось с FATAL EXCEPTION: OkHttp Dispatcher, IllegalStateException: User must be authorized. Воспроизведение: войти, открыть миссию, выйти через меню аккаунта, повернуть устройство и вернуть ориентацию. Ожидается сохранение экрана авторизации без падения. Наблюдался домашний экран Android. После нового запуска доступна авторизация. Зафиксировано одно воспроизведение. Подтверждение: evidence/TC007-crash.txt.

### Дополнительное наблюдение

BUG-003, приоритет P2. У только что созданной тестовой новости в панели дата создания показана как 02.01.58781 при текущей дате 23.10.2026. Дата публикации при этом корректна. Воспроизведение: создать валидную новость и посмотреть её карточку в панели. Ожидается текущая дата создания. Подтверждение: evidence/TC033-created.png. Тестовая запись после проверки удалена.
